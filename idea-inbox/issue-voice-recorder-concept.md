# ボタン押下中のみ録音するトランシーバー型ボイスレコーダー設計整理

## 1. コアコンセプト（1行）
押している間だけ録音し、思考を短い音声クリップとして能動的に区切って収集する。  

## 2. セッション／クリップの妥当性と代替案
### 妥当性
- **クリップ**は「1回の押下＝1思考断片」という操作モデルと一致しており、ユーザーの意図を直接データに反映できる。  
- **セッション**は「1つのテーマ（例：今日の振り返り）」に複数クリップが紐づく構造で、将来のAI投入単位としても自然。  

### 代替案（必要に応じて）
- **バッチ（Batch）**: セッションより軽量な概念。アプリ起動〜終了の間を1バッチとし、後からまとめ直す運用向け。  
- **ストリーム（Stream）**: 連続した押下を時系列ストリームとして扱い、UIで区切りだけ可視化する。編集/再構成が前提の設計。  
- **タグベース**: セッションを固定せず、クリップにタグを付けて後から束ねる方式（探索性重視）。  

> MVPでは「セッション＋クリップ」で十分。将来、バッチやタグで補強する設計余地を残す。  

## 3. MVPとして最小限に必要な画面・状態・データ構造
### 画面
1. **録音画面（メイン）**
   - 押している間だけ録音する「プレス＆ホールド」ボタン
   - 録音中インジケータ（波形／点滅アイコン）
   - セッション名（編集可）
2. **セッション内クリップ一覧**
   - クリップの時系列リスト
   - クリップ再生（最低限の再生/停止）

### 状態
- アプリ状態
  - `Idle`（待機）
  - `Recording`（録音中）
  - `Playback`（再生中）
- セッション状態
  - `SessionActive`（現行セッション）
  - `SessionArchived`（後で見返す用）

### データ構造（例）
- `Session`
  - `id`
  - `title`
  - `createdAt`
  - `updatedAt`
  - `clipIds[]`
- `Clip`
  - `id`
  - `sessionId`
  - `filePath`
  - `durationMs`
  - `createdAt`

## 4. Android実装時の注意点（録音制御・UX）
### 録音制御
- **録音開始/停止の遅延最小化**: 押下開始と録音開始のズレを抑える。  
- **AudioRecord/MediaRecorderの選定**: 短いクリップ高速生成ならAudioRecord＋自前書き出しも検討。  
- **ファイル名生成の衝突回避**: タイムスタンプ＋UUID。  
- **バックグラウンド挙動**: 画面ロック/他アプリ遷移時の停止動作を設計（意図せず録音継続しない）。  

### UX
- **押下中のみ録音のフィードバック**: 押し始めで録音開始を明示（振動/サウンド/色変更）。  
- **誤操作防止**: 押下キャンセル時の扱い（短すぎる録音は破棄するか確認）を明確に。  
- **クリップ単位の確認性**: 連続で押した場合でも「どこで区切れたか」が見えるUI。  
- **セッション名編集**: 最初は自動名（日時）で、後から変更可能。
